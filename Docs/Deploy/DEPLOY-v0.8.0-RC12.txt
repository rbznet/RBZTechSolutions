RBZ PC Health v0.8.0 RC12
Boot-aware restart-required repair verification

BASELINE
GitHub main commit:
5062add7e7cf59cb63b734a4a165d2e4539ca5b3
v0.8.0 RC11 add safe RC temp cleanup and report preservation

PURPOSE
RC10c persisted restart-required repair state across reboot, but did not prove
that Windows had actually restarted. Closing and reopening RBZ on the same boot
could incorrectly offer Verify Repairs.

RC12
- State schema becomes 2.
- Adds BootTimeAtRepair from Win32_OperatingSystem.LastBootUpTime.
- Same-boot relaunch shows Restart Required and disables the scan button.
- After a later Windows boot, Verify Repairs becomes available.
- Legacy RC10c state without boot metadata remains verification-ready.
- No automatic reboot.

APPLY
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Patches\Apply-RC12.ps1

TEST 1 - SAME BOOT
1. Launch:
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\RBZHealth.ps1
2. Full Scan.
3. Repair Centre -> Reset Windows network stack.
4. Close RBZ WITHOUT restarting Windows.
5. Check:
   Get-Content "$env:ProgramData\RBZ Tech Solutions\RBZ PC Health\pending-repair.json"
Expected:
- SchemaVersion = 2
- BootTimeAtRepair populated

6. Relaunch WITHOUT reboot:
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\RBZHealth.ps1
Expected:
- button says Restart Required
- button disabled
- banner says Restart still required
- Verify Repairs unavailable

TEST 2 - AFTER REBOOT
1. Restart Windows.
2. Launch RBZ.
Expected:
- button says Verify Repairs
- banner says Restart completed
- status says Windows restart detected

3. Click Verify Repairs.
4. Check:
   Test-Path "$env:ProgramData\RBZ Tech Solutions\RBZ PC Health\pending-repair.json"
Expected: False

Do not commit until both tests pass.
