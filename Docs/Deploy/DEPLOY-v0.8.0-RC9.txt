NEW REPAIR CENTRE ACTIONS

1. Trigger Windows Update scan - LOW
   Requests fresh update detection using Microsoft.Update.AutoUpdate DetectNow
   and UsoClient StartScan where available.
   Important: submission of the request does NOT mean updates were installed.

2. Clear Windows Update download cache - MEDIUM
   Stops BITS/WUAUSERV.
   Clears only SoftwareDistribution\Download.
   Restarts update services.
   Does not reset update history or policy.

3. Repair Windows Update components - MEDIUM
   Stops BITS/WUAUSERV/CryptSvc.
   Renames SoftwareDistribution and Catroot2 with RBZ timestamped backup names.
   Restarts services and verifies recovery.
   More invasive; should follow lower-risk update actions.

4. Reset Windows network stack - MEDIUM / RESTART REQUIRED
   Runs:
   netsh winsock reset
   netsh int ip reset
   Does not restart Windows automatically.
   Can affect VPN/custom networking, so it is never auto-selected.

5. Reset Microsoft Store cache - LOW
   Runs wsreset.exe and verifies command completion.
   Does not uninstall Store apps.

CONTEXT-AWARE PRIORITY MAPPING

- Pending/available update findings:
  -> Trigger Windows Update scan.

- Failed/recent update findings:
  -> Restart Windows Update services first.
  Deeper Windows Update cache/component resets remain manually chosen by technician.

- DNS resolution/cache findings:
  -> Flush DNS resolver cache.

- Other network findings:
  remain manual investigation. Full network stack reset is not automatically mapped.

SAFETY PRINCIPLES
- RBZ navigates/highlights matching actions only.
- It does not auto-tick or auto-run repairs.
- Medium actions retain existing restore-point safeguards.
- Network reset is restart-required.
- Update scan does not claim updates were installed.
- Deeper Windows Update repair is technician-selected only.
